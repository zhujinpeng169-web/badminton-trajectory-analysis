# 羽毛球轨迹分析交付文档

## 1. 交付内容

本次交付针对 `41.MP4`，输出逐帧羽毛球和两名运动员坐标，并基于球场标定生成运动学与羽毛球轨迹分析结果。

最终结果位于 `output_coordinates/final/`：

| 文件 | 内容 |
|---|---|
| `41_coordinates_locked.csv` | 13,344 帧逐帧坐标、展开球场坐标、速度、方向变化、异常标记和坐标来源 |
| `41_coordinates_locked_ball_analysis.json` | 羽毛球轨迹汇总指标 |
| `41_locked_tracking_report.md` | 身份锁定、光流补偿和质量诊断 |
| `final_analysis_tables.md` | 中文版最终分析表格 |

标定和方法说明位于 `output_coordinates/reference/`，文件索引见 `output_coordinates/README.md`。

## 2. 数据处理流程

1. 读取 `output_tracknet/41_ball.csv` 中的逐帧羽毛球检测结果。
2. 使用 YOLO 姿态模型和 ByteTrack 检测运动员。
3. 使用球场内部过滤，排除球场外候选目标。
4. 使用历史 `track_id` 和上一位置锁定近端、远端逻辑身份。
5. 检测短暂缺失时使用 Lucas–Kanade 光流补偿，最多连续 10 帧。
6. 对每个坐标记录来源：`detect`、`flow` 或 `missing`。
7. 使用球场四点进行单应性变换，将像素坐标转换为 `6.1 m × 13.4 m` 的展开球场坐标。
8. 根据相邻帧位置计算距离、速度、方向变化和异常跳变。
9. 生成逐帧 CSV、JSON 汇总和中文分析表格。

## 3. 球场标定

当前标定点顺序为 `top_left, top_right, bottom_right, bottom_left`：

```text
TL=(291,314), TR=(690,314), BR=(951,535), BL=(48,535)
```

视频坐标原点在左上角，x 轴向右，y 轴向下。完整标定信息见 `output_coordinates/reference/court_points_41.json`。

## 5. 指标解释和限制

- 有效帧率表示存在坐标的比例，不等于检测准确率。
- 运动员速度超过 `8.5 m/s` 的相邻跳变不计入运动距离和平均速度，但原始坐标和来源仍保留在 CSV 中。
- 羽毛球异常跳变通过 `ball_jump_flag=1` 标记，并从过滤后速度、距离汇总中排除。
- 羽毛球速度和轨迹距离是单目视频二维坐标经单应性变换后的投影量，不是真实三维物理量。
- `flow` 坐标是补偿值，`missing` 不应解释为运动员静止。
- 当前视频被按一个完整回合处理；没有额外的击球类型、落点和人工真值标注，因此不能据此独立证明检测准确率、MOTA 或 IDF1。

## 6. 复现命令

在仓库根目录运行：

```bash
./.venv/bin/python pipeline_code/export_frame_coordinates.py \
  --video 41.MP4 \
  --ball-csv output_tracknet/41_ball.csv \
  --output output_coordinates/final/41_coordinates_locked.csv \
  --device mps
```

脚本会同时生成同名的 `*_ball_analysis.json`。运行前需要安装 OpenCV、Ultralytics、NumPy，并准备 `yolov8s-pose.pt` 权重。
